### T-4945 · Validate the hard-shadow threshold against labelled data + visual A/B
**Status:** Ready | **Profile:** P1-feature-worker
**Found by:** [[T-4800]] SPACINI29 evidence run, 2026-07-28

Two calibration gaps, both needing data the repo does not have yet.

**Hard-shadow threshold.** `HardShadowEvidenceFraction` was 0.01, which fired on 86/86 SPACINI29 images —
no discrimination, while trimming 6% off the bottom of every centred image. Now **0.05** (`ClassifyConfig.json:69`,
23/86 fire), chosen by the user against the measured distribution (min 0.0113 / median 0.0371 / p90 0.0702 /
max 0.1243). That is a reasoned choice on an *unlabelled studio set*, not ground truth. Label a set for
hard vs soft shadow and re-tune; `SubjectDetectionResult.HardShadowStrippedFraction` carries the raw
per-image measurement so this needs no re-instrumenting. The user intends to refine the shadow detector
itself later, which will change the distribution.

**First labelled pass, 2026-08-25 (evidence harness on 6 CiMini images, 5 measured).** The `difficult
shadows/` folder this ticket was originally meant to use no longer exists (removed from CiMini during the
same session's golden recapture — every filename in it embedded an 8-digit ID with no matching Excel row,
so it had no place in the matching golden; if those files exist elsewhere they were not recovered here).
Replaced with a fresh 6-image set instead, all 6 Photoshop-edited by the user and all 6 confirmed hard
(user definition: either a strong-gradient shadow, or a shadow that needs special attention to process
correctly) — no soft control in this sample:

**Finding: 0 of 5 confirmed-hard images cross the old 0.05 threshold.** The entire hard population measures
0.0096–0.0407, all below threshold. Unambiguous on its own — 0.05 was too high.

**Decision (user, 2026-08-25): `HardShadowEvidenceFraction` set to 0.0082** (`ClassifyConfig.json:69`,
`//JB: 0.0082 value set based on experience`), below this sample's minimum so all 5 measured hard examples
would now fire. **Caveat for whoever picks this up next:** 0.0082 is also below SPACINI29's own measured
minimum (0.0113, same file, line above) — by that dataset's evidence this reproduces the original 0.01's
failure mode, firing on all 86/86 SPACINI29 images with no discrimination. No comparison against CiMini's
ordinary (non-hard-shadow) population was run before setting this value — that measurement is still the
open item if false-positive rate on normal images becomes a problem in practice.

**Still open:** the centering A/B half of this ticket (untouched), and — if the false-positive concern
above turns out to matter — measuring `HardShadowStrippedFraction` across ordinary CiMini/SPACINI29 images
to see how many now cross 0.0082.

**Centering A/B.** [[T-4850]] asked that the subject box show "equal-or-better centering" than the legacy
salient box. Measured over 71 promoted images: close agreement on the bulk (centre shift median 15.5px on
~3500px images, 51/71 within 50px, area ratio median 1.027) with a tail of ~20 disagreements clustered at
mid confidence (0.48–0.61). Geometry alone cannot say which box is *better* centred — eyeball the tail
(port `save_debug_overlay` from the reference prototype) or score against labelled product bounds.
