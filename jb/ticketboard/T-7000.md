### T-7000 · Successful jobs never delete their artifact folder
**Status:** Ready | **Profile:** P1-feature-worker
**Found by:** disk exhaustion during the T-5010-era AI-toggle verification sweep, 2026-08-12

`LocalArtifactStore` writes every job's normalized images and `lambda/*.json` under a per-job temp
folder, but nothing ever removes that folder once the job succeeds. This ticket adds a delete path so
disk usage stops growing without bound, while keeping result re-fetch inside the retention window
working.

**Problem(s):**
- `LocalArtifactStore` roots every job at `%TEMP%/PRISM/{jobId}` (`RootFolderName = "PRISM"`,
  `JobFolder(Guid)`) and writes the normalized images plus `lambda/*.json` there. Nothing ever deletes
  that folder for a job that succeeds — `IArtifactStore` exposes no delete operation at all, only
  `JobFolder` / `LambdaDocumentPath` / `SaveLambdaDocument` / `LoadLambdaDocument`. **Cause:**
  `PrismJobCoordinator.RemoveExpiredJobs` is the only retention mechanism, and it removes the in-memory
  `PrismApiJob` entry from the `jobs` dictionary once `Jobs.JobRetentionPeriodInHours` (24) has passed —
  it never touches the filesystem. `PrismProcessIngressReader.CleanUpJobTempDir` exists but is wired only
  to the three *rejection* paths (`REQUEST_TOO_LARGE`, field errors, below minimum image/excel counts),
  i.e. jobs that never ran. **Effect:** every successfully-processed job leaks its entire working set
  permanently. **Consequence:** measured 33.4 GB accumulated in a single afternoon of dataset sweeps; it
  never returns on its own and the operator has no signal until the disk fills. Open.

**Decision(s):**
- Acceptance target (decided at ticket authoring): a completed job's `%TEMP%/PRISM/{jobId}` folder must
  be gone once its result is no longer retrievable — either deleted when the job reaches terminal state
  and its result has been read, or at the latest when `RemoveExpiredJobs` evicts the record. Deleting
  must not break a result re-fetch inside the retention window (`GET /PRISM/jobs/{jobID}/result` reads OK/KO
  bytes back off disk for ZIP format), so tie the delete to eviction rather than to completion unless the
  read path is proven independent of disk.
- Implementation pattern (decided at ticket authoring): reuse the pattern that already exists in the
  codebase rather than invent a new one — the match-lite route already cleans up after itself
  (`PrismMatchLiteIngressResult.cs:22`, `PrismMatchLiteIngressReader.cs:85`), and cleanup failures
  (`IOException` / `UnauthorizedAccessException`) must stay non-fatal, swallowed exactly as
  `CleanUpJobTempDir` already does. Adding a delete member to `IArtifactStore` is in scope; changing any
  other member of that interface is not.
- Scope boundary (decided at ticket authoring): disk lifecycle only. Do not change
  `JobRetentionPeriodInHours`, the artifact-bus co-deployment contract, or where the store is rooted.

**Test(s):**
- A test must assert the job folder is gone after `RemoveExpiredJobs` eviction. Not yet run.
