### T-7000 · Successful jobs never delete their artifact folder
**Status:** Ready | **Profile:** P1-feature-worker
**Found by:** disk exhaustion during the T-5010-era AI-toggle verification sweep, 2026-08-12

`LocalArtifactStore` roots every job at `%TEMP%/PRISM/{jobId}` (`RootFolderName = "PRISM"`,
`JobFolder(Guid)`) and writes the normalized images plus `lambda/*.json` there. **Nothing ever deletes
that folder for a job that succeeds.** `IArtifactStore` exposes no delete operation at all — only
`JobFolder` / `LambdaDocumentPath` / `SaveLambdaDocument` / `LoadLambdaDocument`.

**Cause:** `PrismJobCoordinator.RemoveExpiredJobs` is the only retention mechanism, and it removes the
in-memory `PrismApiJob` entry from the `jobs` dictionary once `Jobs.JobRetentionPeriodInHours` (24) has
passed — it never touches the filesystem. `PrismProcessIngressReader.CleanUpJobTempDir` exists but is
wired only to the three *rejection* paths (`REQUEST_TOO_LARGE`, field errors, below minimum image/excel
counts), i.e. jobs that never ran. **Effect:** every successfully-processed job leaks its entire working
set permanently. **Consequence:** measured 33.4 GB accumulated in a single afternoon of dataset sweeps;
it never returns on its own and the operator has no signal until the disk fills.

The pattern already exists in the codebase and just was not applied here — the match-lite route cleans
up after itself (`PrismMatchLiteIngressResult.cs:22`, `PrismMatchLiteIngressReader.cs:85`).

**Acceptance:** a completed job's `%TEMP%/PRISM/{jobId}` folder is gone once its result is no longer
retrievable — either deleted when the job reaches terminal state and its result has been read, or at the
latest when `RemoveExpiredJobs` evicts the record. Deleting must not break a result re-fetch inside the
retention window (`GET /PRISM/jobs/{jobID}/result` reads OK/KO bytes back off disk for ZIP format), so
tie the delete to eviction rather than to completion unless the read path is proven independent. A test
must assert the folder is gone after eviction. Cleanup failures stay non-fatal (`IOException` /
`UnauthorizedAccessException` swallowed) exactly as `CleanUpJobTempDir` already does.

**Scope boundary:** disk lifecycle only. Do not change `JobRetentionPeriodInHours`, the artifact-bus
co-deployment contract, or where the store is rooted. Adding a delete member to `IArtifactStore` is in
scope; changing any other member is not.
