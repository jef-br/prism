### T-5140 · Tx_ProblemImageProcessor reports pre-upscale output metadata
**Status:** Ready | **Profile:** P1-feature-worker
**Found by:** [[T-5010]] review, 2026-07-31; split out as a separate issue 2026-08-12

`Tx_ProblemImageProcessor` writes manifest output geometry using pre-upscale dimensions even when the
image is upscaled, so the manifest under-reports size and scale for any image on that route. Originally
one of two "dormant sizing defects" raised under T-5010; the route's blast radius has since shrunk
because of an unrelated rework, so it needs re-measuring before it's fixed.

**Problem(s):**
- `Tx_ProblemImageProcessor.Transform` (`Tx_ProblemImageProcessor.cs:50`) computes
  `OutputRecord.OutputWidth`/`OutputHeight`/`ScaleFactor` via `ComputeSafeResizeTarget(InputImage.Width,
  InputImage.Height, ...)` — the pre-upscale dimensions. `ImagePreProcessor.ScaleGeometryToUpscaledImage`
  deliberately never updates `lambda.Width`/`.Height` (they are the original-resolution contract the
  upscale manifest reports against). Effect: when an image on this route gets upscaled, `ProcessedBytes`
  reflects the upscaled size while `OutputWidth`/`OutputHeight`/`ScaleFactor` in the manifest still report
  the original pre-upscale numbers, so manifest metadata is wrong (reports smaller dimensions /
  `ScaleFactor` 1.0) for any image that both routes to `Tx_ProblemImageProcessor` and gets upscaled. Open.
- Originally raised in [[T-5010]] as one of two "dormant sizing defects," measured there at ~57/86 images
  on SPACINI29. T-5010 has since removed the phenotype/det-slot gate from `ImageTransformer.SelectTransformer`
  entirely (2026-08-11 DetailCropper rework), so `Tx_ProblemImageProcessor` is now reached only when
  `BoundingBox` is null (e.g. failed subject detection), not on ~57/86 images as originally measured — blast
  radius shrank a lot. Still a live, unfixed defect for whatever does reach that path. Open.

**Test(s):**
- Re-measure blast radius against current routing before fixing — do not reuse the old 57/86 figure, it
  predates the T-5010 gate removal. Not yet run.
