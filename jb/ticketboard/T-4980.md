### T-4980 · CiMini E2E golden is red, and `dotnet test` cannot see it
**Status:** Review | **Profile:** P1-feature-worker
**Review:** Request Changes (2026-07-31)
**Found by:** [[T-4970]] measurement, 2026-07-30

**Reviewer verdict (2026-07-31): Request Changes — the golden passes, but not for the reason the code
gives.** The reviewer ran the pipeline directly and confirmed `CARDIGAN_MAGENTA76_DETAIL.jpg` now
returns `Ok` / `90861052_det2.jpg` / `DetOrder=2`, matching the golden. Then it traced the geometry and
found the fix does not work the way `d808398` describes.

*The full-frame `BoundingBox` this diff writes is dead code.* `ImagePreProcessor.PreprocessAsync`
overwrites `lambda.BoundingBox` unconditionally at line 89 via an independent `DetectSalientBoundingBox`
call, and `Tx_DetailCropper.cs:95` — the transformer that actually ran on this image — reads
`lambda.BoundingBox`, not `lambda.Subject.Box`. **Cause:** the write happens at Matched, the overwrite at
Transform. **Effect:** nothing downstream ever sees the box this fix computes.

*What actually fixes the image is `IsWholeFrameFallback = true`, used against its own documented
meaning.* `ImageTransformer.PreferSubjectGeometry` (`ImageTransformer.cs:97-107`) is gated on
`IsWholeFrameFallback: false`, so setting it true blocks promotion of the mis-boxed 471px collar fold and
leaves the legacy salient box in place — which happens to clear the 570px floor. But
`SubjectDetectionResult.cs:36-37` defines that flag as *"the detector found no subject… the Transformed
stage ignores the box and keeps its legacy salient bbox"* — the opposite of this diff's stated intent
that the frame *is* the subject. **Consequence:** the ticket's headline defect is fixed by suppressing a
different bug through a flag that now means two contradictory things, and it holds only while the legacy
detector keeps producing an adequate box for this image. Fragile, and misleading to the next reader.

*The predicate has no safety margin.* `intersection-count == 4` carries no confidence or area gate, so a
cropped model shot where hair, a hand or a prop touches all four edges while the garment is a sub-region
also reads 4 and gets cropped to the literal full frame — silently worse than the classical-CV attempt it
replaces. Planner input, not a Developer defect: the ticket did not specify this case.

*[[T-4990]] cuts the other way on the same predicate.* That ticket measured the detector as only ever
under-counting. A genuinely full-bleed image that reads 2 or 3 instead of 4 means this short-circuit
silently never fires and the image falls through to the exact classical-CV path that caused the original
defect. No `>= 3` hedge was added.

*The commit does not build standalone.* At `d808398`, `Prism.Core.Contracts.csproj` already references
`SubjectDetectionResult.cs` while the file on disk is still `SubjectDetection.cs` declaring
`SubjectDetection`; the rename lands one commit later in `aa2d297`. **Consequence:** `git bisect` and any
per-commit CI break on this commit. (HEAD is fine — verified building clean.)

*Outstanding item 2, the visibility gap, is untouched.* The diff changes only `FeatureAnalysisService.cs`
and one `.csproj` line. No test project reads the goldens; `PipelineIntegrationTests.cs:127` still asserts
only the `_det\d+\.\w+$` regex.

**Attack point that came back clean:** the T-2600 ordering rule holds. `intersection-count` is written by
`WriteEdgeIntersections` (`ImageFeatureAnalyzer.cs:227-233`) inside `Analyze()` at Classified, and read by
`DetectSubject` from `Refine()` wave 3 at Matched — populated before it is read, no UNKNOWN-forever hazard.

**To clear this verdict:** promote the full-frame box through the documented path, or rename/extend the
`IsWholeFrameFallback` contract so it honestly covers both meanings; reorder or squash the csproj rename
so the commit builds standalone; and add an xUnit test for the short-circuit branch including a
false-positive case.

⚠️ **The CiMini gate is still red at HEAD, on different images.** Re-run during review: 10 issues, all
`DetOrder`/`FinalFileName` mismatches on `2021_3024_46_A/B.jpg` and three `Pareo_exotica*.jpg`. No
`CARDIGAN` and no `PREPROCESS_TOO_SMALL` — this ticket's own defect is genuinely gone. The reviewer read
these as pre-existing debt because `Order/` contains no `BoundingBox`/`Subject` references. **That
reasoning is incomplete and the alternative should be checked first:** [[T-4970]]'s `07c886b` inserted
`back-on-model-partial` det slots across five product types and shifted bottomwear lifestyle/label/material
one slot later, which changes `DetOrder` and `FinalFileName` by design without touching `Order/` at all.
A pareo is beachwear that plausibly maps to bottomwear. If that is what these are, the CiMini goldens need
re-blessing and there is no bug to fix. Confirm which before anyone chases them as defects.

`pwsh test/ci/Invoke-CiPipeline.ps1 -Mode Full -Dataset CiMini` failed on four issues, all one image —
`CARDIGAN_MAGENTA76_DETAIL.jpg` expected `Ok`/`90861052_det2.jpg`, got `Ko` with
`PREPROCESS_TOO_SMALL — Salient object 471px < minimum 570px`.

**Original cause:** T-4920 deliberately changed the too-small KO to measure the **promoted** subject box
rather than the legacy salient box, and this 959×1013 detail shot promotes to 471px — under the 570px
`MinInputSizeInPixels` floor.

**Root cause found and fixed (commit `d808398`, 2026-07-31):** the classical-CV `SubjectDetector` mis-boxed
a collar fold instead of the garment, because a full-bleed shot has no clean background ring to fit a plane
against. `SubjectEdgeDetector` already measures edge intersection at the Classified stage, so
`FeatureAnalysisService` now short-circuits to a whole-frame result when `intersection-count` is 4 — the
frame *is* the subject. This answers the decision the ticket was holding open (new KO vs T-4920 defect):
neither — the box was wrong.
