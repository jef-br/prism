### T-4950 · SubjectMask crosses the service boundary unread
**Status:** Ready | **Profile:** P1-feature-worker
**Found by:** [[T-4800]] completion pass, 2026-07-28

`SubjectDetectionResult.MaskPng` is a full-resolution binary PNG per image, asserted in tests, but no
production code reads it — Transform routes and crops on `Box` plus the intersect flags, and T-4870's
evidence deliberately excludes the pixel mask. **Cause:** built ahead of a v2 consumer (mask-aware fill
/ seam-carving, deferred). Since [[T-4800]] moved detection into the Classify refinement chain, the mask
is serialized across the Matching→Transform HTTP boundary in a distributed deployment — it previously
never left the process. **Consequence:** every image pays a base64 PNG round-trip for a payload nothing
consumes; on ~1900 images that is real bandwidth for zero benefit. Not a correctness bug, not urgent.

**Partly overtaken by [[T-5030]], 2026-08-04 — the decision is still open, the framing is not.** T-5030
deleted `AlphaSubjectCapture` and the whole alpha path, so `classical-cv` is now the only producer that
encodes a `MaskPng` (it used to be two). That shrinks the unread payload but doesn't answer the
question. Measure against current behaviour, not a two-producer description, and ignore the deleted
`AlphaSubjectCapture.cs` when reading the Files list below.

**Problem(s):**
- Unread mask payload crossing a service boundary for no consumer (see above).

**Decision(s):**
- Keep as-is; add `[JsonIgnore]` so it stays in-process; or gate production behind a config flag until
  a real consumer exists — not yet chosen.

**Test(s):**
- Measure the per-image payload size first, to size the actual cost before deciding.
