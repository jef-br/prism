### T-5050 · `multiple-products` is never written false, so one phenotype is unreachable
**Status:** Ready | **Profile:** P1-feature-worker
**Split from:** [[T-4000]] item 1, 2026-08-05 — second of the 11 per-analyzer calibration questions to
get its own ticket, after [[T-5000]].

`Analyzer_MultipleProducts` only writes `multiple-products = true` when YOLO returns more than one
object; it never writes `false`, so single-product images read `UNKNOWN` and any phenotype gated on the
flag can never resolve. Fixing the write-false path is entangled with telling a genuine multi-product
shot apart from a same-class pair (shoes) and from a person alongside a product.

**Problem(s):**
- `Analyzer_MultipleProducts` treats "not multiple" as absence of evidence rather than as a measurement:
  it only writes `multiple-products = true` on a >1 YOLO detection, never `false`. Effect: the feature
  reads `UNKNOWN` on every single-product image, and `PhenotypeRuleSet` treats `UNKNOWN` as satisfying
  nothing (`PhenotypeRuleSet.cs:125`). Consequence: `on-model-with-accessories`, which hard-requires
  `multiple-products = true`, can never be assigned on any image where the detector is right, and every
  rule that would want to *exclude* multi-product shots has no signal to read. Measured by [[T-4970]]:
  UNKNOWN on 86/86 SPACINI29 images.
- Flipping the analyzer to write `false` on any single detection is not a one-line fix: the analyzer's
  own doc records that a pair of shoes is two YOLO detections and would read `multiple-products = true`,
  which is wrong — it is one product. A naive fix just moves the error from "always unknown" to "false
  positive on footwear."

**Decision(s):**
- How to make the analyzer emit a genuine boolean without breaking the same-class-pair case is
  undecided: either product-type-aware handling or a same-class-pair exemption. Either approach
  interacts with `Analyzer_HasHuman`, since a person plus a product is also two detections — the fix
  must also decide, and state explicitly, whether a person counts toward the product count. (open)

**Test(s):**
- Test fixtures already in-repo, no new dataset needed: footwear pairs `2426834-7558_*` (3 shots) and
  the `F-MODE-GO-…-SANDALS-…` set in BE tests exercise the same-class-pair case a naive fix would break;
  single-product bags `OMB-E166-BV_*`, `OMB-E180-BV_*`, `OMB-E181-CVW_*` exercise the plain
  single-product case; all 86 SPACINI29 images exercise on-model single-product. (not yet run)
- Acceptance test: `multiple-products` must carry a KNOWN value on every image where YOLO ran; a shoe
  pair must read `false`; a genuine accessories shot must read `true`; report the confusion matrix on
  the images listed above. (not yet run)
