How PRISM sorts product photos

A plain-language guide to what the system does with the photos and Excel files you give it.

The job in one sentence: you give PRISM a batch of product photos and the Excel files that describe the products. PRISM works out which product each photo belongs to, renames each photo to that product's number, puts the photos in the right order, improves them, and hands everything back — with a report that explains what happened to every single photo.
In: Pareo_exotica_F1.jpg + an Excel file where one row describes product 94613033 as a pareo called "Exotica".
Out: 94613033_det9.jpg — same photo, now named after its product and given position 9.

1. The journey of one photo

Every photo travels through the same eight stations, always in this order:

1ReceivedPhotos are unpacked (also from very large zip files) and checked.
2Looked atAn AI glances at each photo: is there a person? Which side of the product do we see?
3MatchedThe system finds the product each photo belongs to. This is the heart of PRISM — see below.
4OrderedPhotos of the same product get positions: front first, then back, then details.
5RenamedEach photo gets its final name: product number + position.
6GeneratedMissing photo types can be created from existing ones (for example a close-up crop).
7ImprovedPhotos are straightened, cleaned up and enlarged where needed.
8DeliveredYou receive the renamed photos plus a report on every photo.
Photos are never silently thrown away. A photo that cannot be processed is set aside, and the report always says why. The rest of the batch continues normally.

2. Reading the Excel files

Suppliers send Excel files in every imaginable shape. PRISM handles this by itself:

It finds the table, wherever it is

The header row does not have to be the first row, and column names can be in English, French, Dutch, German, Spanish or Italian. Small typing mistakes in the header are forgiven.

Example: a column called Famille, FamilY id or Familyid is understood as the product-number column every time.

It combines several sheets and files

All sheets of all Excel files are merged into one product list. If the same product appears in several places, the information is combined into a single record.

It rescues rows that have no product number

Some sheets describe products but contain no product-number column at all. PRISM does not throw these rows away. It looks for a code the row shares with a product it already knows — for example a barcode or an article number — and attaches the row to that product.

Example: a catalogue row lists article 106297094700 but no product number. A second file (a bundle list) says article 106297094700 belongs to product 98985645. The catalogue row is attached to product 98985645, and all its extra details (colour, name, size) become usable for matching photos.

It gives meaningless photo names a name from their folder

Some photos have names that say nothing, like 1.jpg or DSCN2365.jpg. If such a photo sits in a folder whose name is meaningful, PRISM borrows the folder name for matching. A folder counts as meaningful only when the folders next to it follow the same one-folder-per-product pattern and part of the folder name actually appears in the Excel.

Borrowed: 1.jpg inside folder earphones_zenith_SH23005 is matched as if it were called earphones_zenith_SH23005 1.jpg — because SH23005 is in the Excel.
Not borrowed: a folder called HD, Web or 800 x 1200 only describes size or quality, so it is ignored. The photo keeps its real name in the delivered files.

It accepts very large deliveries

Zip files up to 16 GB with thousands of photos work fine, including the modern large-zip format that big suppliers use.

3. How a photo finds its product

The system tries a series of checks, from the most certain to the least certain. As soon as one check finds exactly one product, the photo is matched and the search stops. Digit groups in the filename are compared with the product number, the barcode and the reference of every product. Very short numbers like _01 (photo 1 of a set) are ignored, so they cannot cause wrong matches. Numbers written anywhere in a product's row also count.

5. What the report tells you

You seeIt means
OK + new filename + which check matched it The photo was matched, renamed and delivered. The report names the exact check (1–8) that found the product, so a match can always be explained.
No match found None of the eight checks found an owner. Usually the filename carries no usable code and no recognisable words.
Fits several products The clues fit two or more products equally well. PRISM never picks one at random — a wrong photo on a product page is worse than a missing one.
Not in the catalogue The photo names a product number that simply is not in the Excel files. Fix: add the product to the data and run again.
Duplicate photo The exact same image was already in the batch (for example once loose and once inside a zip). Only one copy is processed.
Too small The image has too few pixels to produce good output.

6. What to remember

  • Certain before clever: exact numbers are tried first, AI impressions last.
  • Never guess: a photo is only matched when exactly one product fits.
  • Nothing disappears: every photo appears in the report — matched or set aside with a reason.
  • Messy input is normal: foreign-language headers, multiple sheets, missing product numbers, glued words in filenames and 6 GB zips are all handled automatically.
